# V0.1 版本说明

V0.1 是“不息”个人网站的第一个可持续维护版本。它确立了网站的内容边界、视觉语言与静态发布方式，并完成了 Astro 原生照片系统的第一版实现。

版本标签：`v0.1`

基线提交：`6a2d54c`

## 本版本完成的工作

### 网站基础

- 以 Astro 6、TypeScript、Content Collections 和静态生成为技术基线。
- 建立首页、项目、文章、照片、相册、关于、详情页、RSS、404 与开发环境设计系统页。
- 明确 `projects`、`articles`、`albums`、`photos`、`resume` 的内容边界和稳定地址规则。
- 形成产品、设计系统、领域语言和照片模块实施文档，作为后续迭代依据。

### 视觉与交互

- 建立暖白纸张感、近黑文字与暖橙棕强调色组成的全站设计变量。
- 完成首页、导航、项目卡片、内容列表和页脚的版式统一与响应式适配。
- 加入克制的首页动效与交互反馈，同时支持 `prefers-reduced-motion`。
- 完善移动导航的键盘操作、焦点返回、外部点击关闭和 `Esc` 关闭行为。

### Astro 原生照片系统

- 决定不部署 Afilmory，仅选择性借鉴其增量处理、Manifest 和 URL 驱动查看器思路。
- 建立照片与相册 Content Collections，并为照片、相册和标签生成静态页面。
- 实现保留原始比例的响应式照片网格、显式“加载更多”和无 JavaScript 基础浏览。
- 实现 URL 驱动灯箱，支持前后切换、键盘方向键、`Esc`、焦点锁定与恢复、触摸滑动和浏览器历史。
- 实现本地照片处理脚本，生成 JPG/WebP 响应式发布资产和机器可读 Manifest。
- 实现发布审计，检查缺失资产、尺寸、敏感 EXIF 和未被内容引用的衍生文件。
- 将照片原件目录保持为私有输入，公开目录只保存经过处理的发布资产。

### 验证与版本保存

- `npm run build` 已通过，Astro 检查无错误、警告或提示，共生成 21 个静态页面。
- 照片审计已通过：3 条照片内容、12 个响应式发布资产。
- 已完成桌面端与移动端的页面、导航、照片网格和灯箱检查。
- 当前代码已保存为 Git 标签 `v0.1`，并推送至 `leoyug/Traces`。

## 当前限制

- 当前三张照片主要用于验证设计和处理流程，正式摄影内容仍需逐张筛选、补充说明并确认隐私。
- 网站仍使用部分演示文章、项目和职业信息，上线前需要替换或核实。
- 首版不包含 CMS、数据库、账户、评论、地图、Live Photo、远程图片存储或后台管理。
- 照片处理依赖本地命令和 Git 工作流，暂未建立自动化发布流水线。
- Astro 6 依赖链仍有 npm 安全审计提示；自动修复需要升级 Astro 7，因此未在 V0.1 中跨主版本处理。

## 接下来的计划

### V0.2：真实内容与发布闭环

1. 用真实照片替换设计验证内容，为每张照片补齐准确的替代文本、日期、地点粒度、标签和说明。
2. 核对首页、项目、文章、关于页和职业信息，删除未准备好的演示栏目或内容。
3. 使用一批真实横幅、竖幅和不同尺寸照片压力测试处理脚本、网格布局、分页与灯箱语境。
4. 增加一份简明的照片发布操作清单，将导入、处理、审计、构建和提交串成固定流程。
5. 完成正式域名下的链接、RSS、元数据、分享卡片、404 与移动设备验收。

### 后续候选项

- 评估 Astro 7 升级，处理依赖安全提示并完成回归测试。
- 在真实内容规模增长后，再判断是否需要自动化图片处理、对象存储或轻量 CMS。
- 根据实际阅读和浏览反馈优化照片加载策略、相册导航与内容发现方式。
- 只有在明确需要时，才评估地图、Live Photo、搜索、评论或更复杂的查看器能力。

## 版本原则

后续迭代继续保持纯静态优先、稳定地址优先、隐私优先和无障碍优先。任何新增能力都应先证明其对长期记录或内容阅读有实际价值，再增加运行时、服务端或维护复杂度。
