# 照片模块构建与上线指南

状态：可执行
版本：v1.0
日期：2026-08-13
适用范围：个人网站首版照片模块

## 1. 目标和完成标准

本指南把《个人网站功能方案》中的摄影要求转化为可以直接开发和验收的实现方案。默认首发规模为 1 个相册、约 12 张照片，技术基线为 Astro 6、TypeScript、Content Collections、纯静态生成和局部 React 组件。

照片模块只有同时满足以下条件才算可上线：

- `/photos/`、相册页、标签页和照片稳定地址均可访问。
- 同一套照片列表组件服务于全部照片、相册和标签页面。
- 照片保持原始比例；桌面最多 4 列，窄手机 1–2 列。
- 列表使用“加载更多”按钮，URL 保存加载批次。
- 点击照片后打开 URL 驱动的灯箱；刷新、返回和前进行为正确。
- 灯箱支持前后切换、方向键、`Esc`、焦点锁定、焦点恢复和移动端滑动。
- 线上文件不包含 GPS、作者名、版权、设备序列号等敏感元数据。
- 线上不提供照片原件，只提供限制尺寸的发布资产。
- 无 JavaScript 时仍能浏览首批照片并打开独立照片页。
- 键盘流程、移动端流程、图片性能和 404 均通过上线检查。

## 2. 实施结论

### 2.1 从 Afilmory 采用的思路

- 扫描照片后生成结构化 Manifest，而不是在页面组件里读取 EXIF。
- 根据文件摘要或修改信息进行增量处理。
- 构建时完成方向校正、格式转换、尺寸生成和占位数据计算。
- 列表和灯箱共享同一份照片数据。
- 灯箱状态以照片 URL 为准，而不是只存在于组件内存中。
- 只预加载当前照片相邻的发布资产。

### 2.2 首版不采用的部分

- 不嵌入 Afilmory React SPA 或 Next.js SSR。
- 不复制 `apps/web` 下的相册和灯箱实现。
- 不原样使用当前 `@afilmory/builder`；它的输出目录和缩略图规格与本站不一致。
- 不公开 `originalUrl`，不把 GPS 写进公开 Manifest。
- 不引入 WebGL 查看器、地图、Live Photo、HDR 专用 UI、评论、点赞、账户、后台或远程存储。
- 不做图片缩放手势；首版只支持适应屏幕显示和左右滑动。

## 3. 系统边界

```text
照片原件（本地、非公开）
        │
        ▼
本地照片处理脚本
  ├─ 读取白名单 EXIF
  ├─ 生成响应式发布资产
  ├─ 验证并清除敏感元数据
  └─ 生成 photo-assets.generated.json
        │
        ▼
Astro 构建
  ├─ Content Collections：作者维护的内容
  ├─ Generated Manifest：机器生成的资产信息
  └─ 静态页面 + 照片灯箱 React island
        │
        ▼
静态托管（无数据库、无图片处理服务）
```

关键边界：

- 照片原件不进入 `public/`，默认不进入 Git。
- 发布资产和生成 Manifest 进入 Git，保证 CI 不依赖私人原件。
- CI 只验证发布资产，不重新处理原件。
- 手动内容与机器数据分离，重新生成图片时不得覆盖标题、替代文本、相册和地点确认。

## 5. 内容模型

### 5.1 照片：作者维护字段

建议在 `photos` Content Collection 中使用以下结构：

```ts
const photoSchema = z.object({
  title: z.string().min(1),
  alt: z.string().min(1),
  description: z.string().optional(),
  publishedAt: z.coerce.date(),
  takenAt: z.coerce.date().optional(),
  sourceFile: z.string().min(1),
  albums: z.array(z.string()).default([]),
  tags: z.array(z.string()).default([]),
  location: z.object({
    label: z.string().min(1),
    visibility: z.enum(['public', 'hidden']),
  }).optional(),
  exifOverrides: z.object({
    camera: z.string().nullable().optional(),
    lens: z.string().nullable().optional(),
    focalLength: z.string().nullable().optional(),
    aperture: z.string().nullable().optional(),
    shutterSpeed: z.string().nullable().optional(),
    iso: z.number().int().positive().nullable().optional(),
  }).optional(),
  draft: z.boolean().default(false),
})
```

规则：

- 文件名就是稳定短名；改标题不得改文件名。
- `alt` 和 `publishedAt` 必填。
- `takenAt` 可以隐藏或覆盖 EXIF 时间。
- 地点只允许手动填写城市或地区；不保存坐标。
- `albums` 和 `tags` 必须在构建时校验引用与短名。
- 同一照片可以属于多个相册，但首版相册顺序由相册显式维护。

### 5.2 相册：作者维护字段

```ts
const albumSchema = z.object({
  title: z.string().min(1),
  description: z.string().min(1),
  cover: z.string().min(1),
  photos: z.array(z.string()).min(1),
  dateRange: z.object({
    from: z.coerce.date().optional(),
    to: z.coerce.date().optional(),
  }).optional(),
  locationRange: z.string().optional(),
  publishedAt: z.coerce.date(),
  draft: z.boolean().default(false),
})
```

### 5.3 发布资产：机器生成字段

```ts
type GeneratedPhotoAsset = {
  slug: string
  sourceDigest: string
  width: number
  height: number
  aspectRatio: number
  placeholder: string
  variants: Array<{
    format: 'webp' | 'jpeg'
    width: number
    height: number
    src: string
    bytes: number
  }>
  publicExif: {
    camera?: string
    lens?: string
    focalLength?: string
    aperture?: string
    shutterSpeed?: string
    iso?: number
  }
  processedAt: string
}
```

禁止出现在 Generated Manifest 中的字段：

- GPS 纬度、经度和海拔
- 文件系统绝对路径
- Artist、OwnerName、Copyright
- 相机或镜头序列号
- 手机、账户或软件用户名
- 原件下载地址
- 未经过作者确认的反向地理编码结果

## 6. 图片处理流水线

### 6.1 依赖建议

首版使用以下最小组合：

- `sharp`：方向校正、尺寸缩放、WebP/JPEG 编码。
- `exiftool-vendored`：读取源文件 EXIF，并审计发布文件。
- `thumbhash`：生成轻量占位数据；如果接入成本影响工期，可先使用 CSS 背景色并在上线后补充。

不要让网页端解析 EXIF。所有元数据必须在本地处理阶段确定。

### 6.2 处理步骤

对每张非草稿照片执行：

1. 根据 `sourceFile` 在 `private/photos/` 中定位原件。
2. 计算源文件 SHA-256；摘要未变化且所有发布资产存在时跳过。
3. 读取尺寸、方向和 EXIF。
4. 只提取允许公开的相机、镜头、焦距、光圈、快门和 ISO。
5. 应用 `exifOverrides`；显式 `null` 表示隐藏该字段。
6. 自动旋转并重新编码，不复制原始 metadata profile。
7. 按 480、960、1600、2400 像素宽生成 WebP；不放大小图。
8. 生成 960 和 2400 像素宽 JPEG 作为兼容后备；不放大小图。
9. WebP 初始质量设为 82，JPEG 初始质量设为 86；仅在肉眼检查后统一调整。
10. 生成 ThumbHash 或占位色。
11. 使用 ExifTool 重新扫描所有输出文件，发现敏感字段立即失败。
12. 原子更新 `photo-assets.generated.json`，避免处理中断留下半份 Manifest。

发布资产最大边长为 2400px。它是查看用途的高质量衍生图，不是照片原件。

### 6.3 必须失败的情况

处理或构建遇到以下任一情况应退出非零状态：

- 本地执行 `photos:process` 时找不到照片原件。
- 执行检查或正式构建时找不到 Manifest 引用的发布资产；CI 不要求存在照片原件。
- `alt` 为空。
- 照片短名重复。
- 相册或照片引用不存在。
- 相册封面不在相册中。
- Manifest 中出现禁止字段。
- 输出文件仍含 GPS、序列号、作者或版权字段。
- 输出尺寸或比例与 Manifest 不一致。
- 草稿被包含在正式构建结果中。

## 7. 页面与地址

| 页面 | 地址 | 默认顺序 |
| --- | --- | --- |
| 全部照片 | `/photos/` | `publishedAt` 倒序 |
| 相册 | `/albums/<album-slug>/` | 相册 `photos` 字段顺序 |
| 标签 | `/photos/tags/<tag-slug>/` | `publishedAt` 倒序 |
| 照片 | `/photos/<photo-slug>/` | 稳定地址 |

照片 URL 可以携带浏览恢复参数，但 canonical URL 必须是不带参数的稳定照片地址：

```text
/photos/winter-river/?context=album&value=hangzhou&batch=2
```

参数规则：

- `context` 只允许 `all`、`album`、`tag`。
- `value` 只在相册或标签语境中使用。
- `batch` 是从 1 开始的加载批次。
- 无效参数回退到全部照片，不产生错误或空灯箱。
- canonical、分享地址和 sitemap 均忽略这些恢复参数。

## 8. 照片列表

### 8.1 渲染

- 服务端渲染第一批，每批 12 张。
- 卡片必须使用真实 `<a href="/photos/<slug>/">`，不能用带点击事件的 `div`。
- JavaScript 拦截站内卡片导航并打开灯箱；无 JavaScript 时进入独立照片页。
- 使用 `<picture>`、`srcset` 和 `sizes` 选择发布资产。
- 首屏可能进入视口的前 2 张图片使用高优先级，其余 `loading="lazy"`。
- 图片元素必须带固有 `width`、`height` 和 `aspect-ratio`，防止布局跳动。

### 8.2 布局

首版采用 CSS Grid 行跨度方案，不使用 CSS Columns，也不使用会按“最短列”重排项目的虚拟瀑布流。

- 列表 DOM 顺序就是内容顺序。
- 不使用 `grid-auto-flow: dense`。
- 根据最小卡片宽度自动计算列数。
- 窄手机最少 1 列、通常 2 列；桌面最多 4 列。
- 每次布局改动都必须检查视觉顺序是否仍与 Tab 和屏幕阅读器顺序一致。
- 若浏览器布局差异导致顺序不可靠，回退为普通非密集 Grid；内容顺序优先于填满空隙。

建议实现使用 `grid-auto-rows: 8px` 和固定行间距。卡片宽度变化后，通过轻量 `ResizeObserver` 按下式更新每张卡片的 `grid-row-end`，不改变 DOM：

```ts
const displayedHeight = cardWidth / aspectRatio
const rowSpan = Math.ceil((displayedHeight + rowGap) / (rowHeight + rowGap))
card.style.gridRowEnd = `span ${rowSpan}`
```

测量脚本只负责布局增强；脚本未执行时，卡片依靠 `aspect-ratio` 以普通 Grid 显示。

### 8.3 加载更多和恢复

- 首批 12 张，之后每次增加 12 张。
- “加载更多”是按钮，必须显示剩余数量或明确的动作文本。
- 点击后用 `history.replaceState` 更新 `?batch=N`，不新增无意义历史记录。
- 当前已加载数量、滚动位置和最后聚焦照片写入 `history.state`。
- 从灯箱关闭或浏览器返回后，先恢复批次，再恢复滚动位置和焦点。
- 已加载全部照片后移除按钮，不显示禁用空控件。

## 9. 灯箱

### 9.1 组件边界

`PhotoLightbox.tsx` 是照片模块唯一必须 `client:load` 的大型交互组件。列表的基础内容必须由 Astro 输出，不等待 React 才出现。

优先使用成熟的 Dialog primitive 管理：

- `role="dialog"` 和 `aria-modal="true"`
- 焦点锁定
- `Esc` 关闭
- 关闭后焦点恢复
- 页面背景对辅助技术不可交互

如果使用第三方 Dialog，只采用该无障碍基础能力，不引入完整视觉组件库。

### 9.2 URL 和历史行为

- 点击照片：`pushState` 到照片稳定地址，并记录列表语境。
- 前后切换：使用 `replaceState` 更新当前照片，避免每滑一张产生一层历史。
- 浏览器返回：优先关闭灯箱并回到原列表状态。
- 直接访问或刷新照片 URL：显示同一张照片；关闭时跳转到参数指定的列表，否则回到 `/photos/`。
- 照片不存在：进入定制 404，不得默认为第一张照片。

### 9.3 交互和布局

桌面端：

- 图片区占剩余空间，右侧元数据栏默认展开。
- 元数据栏固定合理宽度，不覆盖图片。
- 左右按钮拥有文字形式的 `aria-label`。

移动端：

- 图片完整适应可视区域。
- 元数据位于图片下方并默认折叠。
- 水平滑动超过距离和速度阈值后切换，垂直页面手势不应被误拦截。
- 首版不支持双击、捏合或滚轮放大。

全部设备：

- 左右方向键切换，边界处不循环。
- 图片变化后更新对话框标题的可访问文本。
- 只预加载上一张和下一张的合适尺寸，不预加载整个相册。
- 尊重 `prefers-reduced-motion`；关闭动效后功能保持完整。

## 10. 元数据展示

公开面板按以下顺序显示，字段缺失时整项隐藏：

1. 标题和描述
2. 拍摄日期
3. 相机与镜头
4. 焦距、光圈、快门、ISO
5. 手动确认的城市或地区
6. 相册
7. 标签

不要显示“未知”“暂无数据”来填充技术字段。标签和相册名称必须是可访问其列表页的链接。

## 12. 开发顺序

以两天完成照片模块为目标：

### 第 1 天上午：模型和处理流水线

- 建立照片、相册集合及 Zod 校验。
- 建立 `private/photos`、发布资产目录和 `.gitignore`。
- 完成单张照片处理、EXIF 白名单和敏感字段审计。
- 完成增量摘要与 Generated Manifest。
- 用 3 张横竖比例不同的真实照片验证输出。

退出条件：能够从原件稳定生成发布资产，审计失败会阻止构建。

### 第 1 天下午：列表和路由

- 完成全部照片、相册、标签和独立照片页面。
- 完成共享 `PhotoGrid`、响应式图片和悬停信息。
- 完成加载更多、URL 批次和无 JavaScript 回退。
- 录入首发 12 张照片和 1 个相册。

退出条件：四类地址可直接访问，移动端和桌面端顺序正确，无明显布局跳动。

### 第 2 天上午：灯箱

- 完成 Dialog、URL 状态、历史记录和浏览语境。
- 完成前后按钮、键盘、焦点锁定和焦点恢复。
- 完成移动端滑动和折叠元数据。
- 完成相邻图片预加载。

退出条件：刷新、返回、前进、直接访问和关闭行为均符合预期。

### 第 2 天下午：验证和上线

- 跑类型检查、内容检查、图片审计和生产构建。
- 用 Playwright 覆盖核心桌面和移动流程。
- 用键盘手动走完列表和灯箱。
- 检查发布产物中不存在原件或敏感 EXIF。
- 检查 404、canonical、noindex、分享地址和部署预览。

退出条件：第 13 节所有 P0 验收项通过。

## 14. 建议脚本和检查命令

项目建立后在 `package.json` 提供统一入口：


建议的最小端到端用例：

1. 从相册打开第 3 张照片，下一张仍属于该相册。
2. 打开灯箱后刷新，仍显示同一照片和相册语境。
3. 从灯箱返回，恢复原批次、滚动位置和触发卡片焦点。
4. 直接访问照片地址并关闭，回到全部照片列表。
5. 关闭 JavaScript，卡片链接仍能打开照片页。
6. 用键盘从列表打开、切换并关闭灯箱，全程不丢失焦点。
7. 审计脚本向测试图片注入 GPS 后必须失败。

## 15. 明确延期

以下能力不应阻塞首发，也不应在两天实施中顺手加入：

- 地图和精确地点
- Live Photo、Motion Photo 和 HDR 专用显示
- WebGL、放大手势和原件下载
- 自动标签、相似照片和智能推荐
- 收藏、评论、点赞和分享弹窗
- 管理后台、数据库和在线上传
- 无限滚动和复杂筛选面板
- 多套瀑布流布局或用户自定义列数
