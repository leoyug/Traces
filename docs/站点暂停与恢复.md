# 站点暂停与恢复

2026-10-16：用户要求暂不公开网站，已开启 Cloudflare 自定义规则暂停访问。后续收到明确恢复上线指令后再关闭此规则。

## 当前开关

- Cloudflare zone：`smileoleo.com`（`4db672379ff32de3eccf13282cc6501e`）。
- 自定义 ruleset：`Smileo public access`，ID `495faf41ac0a4014b4becf73f48debb6`。
- 规则：`Smileo - pause public access (disable this rule to resume)`。
- rule ID：`69a38c78aa16417ea0295ac581180f9e`，ref `smileo_pause_public_access`。
- 匹配主域、www 与 photos 三个域名，Block 动作，`enabled: true` 表示暂停。

主站和图片请求返回 403。www 仍按原来的规则跳转到主域，最终同样返回 403。Workers 部署、Custom Domain、DNS、证书和 R2 对象均保留；workers.dev、版本预览、r2.dev 入口继续关闭。

当前套餐不支持自定义 WAF 拦截响应，因此显示 Cloudflare 默认的 403 页面。

## 恢复公开访问

在 Cloudflare 的 `smileoleo.com` → Security rules（安全规则）中，关闭上面这条自定义规则即可恢复原有部署。只切换该规则，不删除 ruleset，也不修改其他安全规则。

也可以让 Codex“恢复 Smileo 公开访问”，将该 rule 的 `enabled` 改为 `false`。若内容没有变化，恢复无需重新上传网站；若要发布新的内容版本，先完成本地核对、构建、媒体同步和部署，再关闭暂停规则。

恢复后核查首页、www 跳转、图片、RSS 与 404。再次暂停时将同一规则设为 `enabled: true`。

暂停开关独立于 `wrangler.jsonc`；普通部署不会自动恢复公开访问。本地开发不受该规则影响。

本次内容核对后的修改保存于 `codex/content-closeout`，尚未部署。当前被暂停的仍是此前已发布的版本；若希望恢复时使用已过滤草稿的版本，应先合并、构建并部署本次修改，再关闭暂停规则。

官方参考：[WAF 自定义规则](https://developers.cloudflare.com/waf/custom-rules/)、[R2 自定义域名访问控制](https://developers.cloudflare.com/r2/buckets/public-buckets/)。
